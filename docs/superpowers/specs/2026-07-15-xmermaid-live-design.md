# xmermaid-live 设计

状态：已由用户确认  
日期：2026-07-15

## 目标

xmermaid-live 是一个可静态部署的纯前端 Mermaid 工作台。用户可以粘贴一整段包含多张 Mermaid 图表的文本，应用自动提取图表并生成列表；用户选择任意图表后，可以编辑对应源码并实时预览。整个过程只在浏览器内完成，不上传用户文本。

首版以 `/Volumes/Data/Code/xmermaid` 提供的浏览器 SDK 为渲染和语义边界。它当前只支持部分 flowchart 语法，因此应用必须如实展示不支持的图表类型和语法，不能暗示完整 Mermaid 兼容性。

## 已确认范围

首版提供：

- 完整文本粘贴与编辑。
- 多 Mermaid 图表自动提取、列表展示和切换。
- 当前图表独立编辑，并同步回写完整文本。
- 基于 xmermaid WASM 的实时 SVG 预览和结构化诊断。
- URL hash 恢复与分享。
- 当前有效预览的 SVG、PNG 下载。
- 桌面三栏工作区和移动端面板切换。
- 适用于静态站点和非根路径部署的构建产物。

首版不加入拖拽式可视化画布、云端存储、用户系统或 Mermaid.js 兜底渲染。后续若要支持更多图表类型，应先扩展 xmermaid 的生产支持合同，而不是在应用中维护第二套渲染语义。

## 现有能力与变化边界

xmermaid 已提供本应用所需的底层闭环：

- `extractDiagrams(text)` 从 Markdown 的 `mermaid` / `xmermaid` fenced block 中提取多张图，也支持整段文本是一张裸 flowchart。
- `replaceDiagramSource(...)` 依据 source range 将选中图表安全回写原文。
- `XMermaid.renderToSVGElement(...)` 返回 SVG、尺寸和结构化 diagnostics。
- `encodeShareState(...)` / `decodeShareState(...)` 使用 URL hash 保存文档和选中图表。
- `exportDiagram(...)` 基于当前 SVG 导出 SVG 或 PNG。
- 默认 strict 安全策略在 WASM 解析前阻断危险输入，并清理生成 SVG。

现有 `XMermaidLiveEditor` 已验证这些能力能够协作，但它直接生成四栏开发者工作台，内部状态和 DOM 结构不可作为可定制组件使用。xmermaid-live 因此自建应用壳，复用公开的数据、渲染和导出接口，不复制 parser、layout、diagnostic 或 export 规则。

## 用户工作流

### 首次进入

没有 hash 状态时，应用展示一份包含两张 flowchart 的示例文档。用户可以直接试用，也可以全选后粘贴自己的内容。若 URL hash 中存在有效状态，则优先恢复该文档和选中图表。

### 粘贴与提取

“完整文本”编辑器是唯一数据源。输入事件发生后，应用立即重新提取图表并刷新列表；WASM 预览使用短防抖，避免每次按键都启动一次渲染。

首版识别规则与 xmermaid 公开合同一致：

1. 扫描完整文本任意位置的 ```` ```mermaid ```` 与 ```` ```xmermaid ```` fenced block，可同时提取多张图。
2. 当没有 fenced block 且整段去除首尾空白后以合法 `graph` / `flowchart` 声明开始时，将其识别为一张裸图。
3. 不猜测普通自然语言中的无围栏 Mermaid 片段，因为它们没有可靠结束边界；这种输入显示粘贴格式提示，不做有损拆分。

### 列表切换与编辑

列表按文档顺序显示“图表 1、图表 2……”以及类型和起始行。选择列表项会更新“当前图表”编辑器和预览，但不会复制文档状态。

编辑当前图表时，应用用该项的 source range 替换原文，再从新文本重新提取全部图表。选中状态优先保持原索引；当删除导致索引越界时，选择最近的剩余图表。切回“完整文本”时，用户看到的是已经回写后的原文。

### 预览、诊断与导出

每次预览请求都有递增编号。只有最新请求可以更新页面，较慢的旧请求完成后必须被丢弃。

渲染成功时，预览区替换为最新 SVG，并在旁边显示 warning 或成功状态。渲染失败时，保留最后一次成功 SVG，明确标注“预览未更新”，同时展示 xmermaid 的 diagnostic code、消息和可用行号。没有成功预览或成功预览已落后于当前源码时，导出按钮必须禁用，避免下载错误图表。

## 界面设计

### 桌面端

页面由顶部工具栏和三栏工作区组成：

```text
┌──────────────────────────────────────────────────────────────────┐
│ xmermaid live       分享链接          下载 SVG   下载 PNG        │
├──────────────┬────────────────────────┬──────────────────────────┤
│ 图表列表      │ 完整文本 | 当前图表     │ 实时预览                 │
│              │                        │                          │
│ 图表 1       │ 源码编辑区              │ SVG                      │
│ 图表 2       │                        │                          │
│ 图表 3       │                        ├──────────────────────────┤
│              │                        │ diagnostics              │
└──────────────┴────────────────────────┴──────────────────────────┘
```

图表列表使用固定窄栏；编辑和预览平分剩余宽度。编辑区的两个标签不会创建两份内容：“当前图表”始终是完整文本中选中 range 的投影。

### 移动端

窄屏不压缩三栏，而是在“图表、编辑、预览”三个面板间切换。选择图表后自动进入编辑面板，用户可以显式切到预览。顶部主要动作保留可触达的文字或图标加可访问名称。

### 空状态与可访问性

- 没有图表时，列表和预览显示可操作的 fenced block 粘贴示例。
- 列表项使用按钮语义并标记当前选中项。
- 编辑器有可见标签；诊断区域使用适当 live region，但避免每次按键产生打断式播报。
- 所有核心操作支持键盘完成，焦点样式不能只依赖颜色。

## 模块与职责

保持模块数量最小，只建立三个真实责任边界：

### 文档模型

文档模型封装“从完整文本得到图表列表”和“把图表源码写回完整文本”两项能力。内部委托给 xmermaid 的 `extractDiagrams` 与 `replaceDiagramSource`，对应用只暴露当前文本、提取结果和替换结果，避免 UI 直接维护 source range 算法。

### 预览运行时

预览运行时负责防抖、请求编号、XMermaid 实例调用、最后成功 SVG、diagnostics 和导出就绪状态。它隐藏 WASM URL 配置和 stale render 处理，让 UI 只消费明确的 `idle`、`rendering`、`ready`、`error` 状态。

### 应用壳

应用壳维护少量交互状态：完整文本、提取结果、选中索引、活动编辑标签和移动端活动面板。它渲染列表、编辑器、工具栏和预览状态，并把用户动作送到文档模型或预览运行时。分享和导出直接复用 xmermaid helper，不增加平行抽象。

## 数据流

```text
粘贴 / 输入完整文本
        │
        ▼
    文档模型 ──────► 图表列表
        │                │
        │                └──选择图表──► 当前源码投影
        │                                  │
        │                         编辑并按 range 回写
        │                                  │
        └──────────────────────────────────┘
                           │
                           ▼
                    预览运行时（防抖）
                           │
                           ▼
                  xmermaid JS + WASM
                           │
                    SVG + diagnostics
```

分享只序列化完整文本和选中图表标识到 hash。恢复时先解码完整文本，再重新提取图表；hash 中的选中项无效时回退到第一张图。应用不把提取结果或 SVG 放入 hash，避免保存派生状态。

## 静态构建与 WASM

应用使用 Vanilla TypeScript、CSS 和 Vite。开发阶段通过本地 package dependency 消费 `/Volumes/Data/Code/xmermaid`，不从源仓复制 TypeScript 或 Rust 代码。

构建前将安装包中的 `xmermaid_wasm_bg.wasm` 复制到应用公共资源目录，运行时向 xmermaid 传入相对于当前页面解析的明确 `wasmUrl`。Vite 使用相对资源基址，使生成的 `dist/` 可部署到域名根路径或任意子路径。最终部署只需要 `dist/`，不需要 Node、Rust、后端服务或相邻的 xmermaid 源仓。

## 安全与隐私

- 保持 xmermaid 默认 strict security level 和 SVG sanitization，不执行 Mermaid click callback，不信任 HTML label。
- 用户文档只保存在页面内存和 URL hash 中；应用不发起分析、存储或遥测请求。
- UI 文本通过 DOM `textContent` 或等价安全绑定呈现，不能把源码或 diagnostic message 作为任意 HTML 注入。
- 导出只使用与当前源码匹配的已清理 SVG。

## 测试设计

### 单元测试

文档模型测试覆盖：

- 混合 Markdown 中多个 `mermaid` / `xmermaid` fenced block 的顺序、源码和行号。
- 整段裸 flowchart。
- 无图表文本和不闭合 fence。
- 当前图表替换后完整文本的其余部分保持不变。
- 插入、删除图表后选中索引的回退行为。

预览运行时测试覆盖：

- 输入防抖只渲染最终源码。
- 较旧异步请求不能覆盖较新 SVG 或 diagnostics。
- 失败保留最后成功 SVG，但关闭过期导出。
- 只有与当前选中源码匹配的成功结果可导出。

### 浏览器测试

使用真实构建和真实 xmermaid WASM 验证用户路径：

1. 粘贴含多张图的文档后，列表数量与顺序正确。
2. 切换图表后，预览 SVG 内容随选中项变化。
3. 编辑当前图表后，完整文本对应 fenced block 被回写并重新渲染。
4. 不支持图表和无效 flowchart 显示正确诊断，不覆盖最后成功预览。
5. hash 分享在新页面恢复完整文本和选中项。
6. SVG 与 PNG 导出只在当前预览有效时可用。
7. 桌面三栏和移动面板切换均可操作。

静态部署 smoke 从生产 `dist/` 启动普通 HTTP server，并从子路径打开页面，确认 HTML、JS、CSS 和 WASM 都能加载且没有控制台错误。浏览器测试同时监控网络，证明应用除自身静态资源外不上传用户文本。

### 完成门禁

完成前必须通过：

- TypeScript typecheck。
- 单元测试。
- Vite production build。
- 生产构建的真实浏览器端到端测试。
- 静态子路径部署和 WASM 加载 smoke。
- `git diff --check`。

## 实施顺序

1. 建立最小 Vite/TypeScript 静态工程和本地 xmermaid 依赖，先证明 production build 能加载真实 WASM。
2. 以测试锁定文档提取、range 回写和选中状态规则。
3. 实现应用壳、三栏布局和完整文本/当前图表编辑闭环。
4. 实现带请求编号的实时预览、诊断和空/错误状态。
5. 接入 hash 恢复、分享和 SVG/PNG 导出。
6. 完成移动布局、键盘与可访问性处理。
7. 运行生产浏览器测试和静态子路径部署验证，修复所有硬失败后交付。

## 成功标准

用户在一个静态页面中粘贴包含多张 Mermaid fenced block 的完整文本后，无需上传或手动拆分即可看到图表列表；任意切换、编辑一张图都会安全回写原文并得到最新 xmermaid SVG 或明确诊断。构建后的 `dist/` 在普通静态服务器的子路径上能够独立运行，真实 WASM 加载、分享恢复和导出路径均有浏览器证据。
