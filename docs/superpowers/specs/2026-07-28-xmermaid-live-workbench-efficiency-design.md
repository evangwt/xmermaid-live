# xmermaid-live 工作台效率优化设计

状态：已通过对话确认，待书面规格复核
日期：2026-07-28

## 目标

这次变化把已经完成的深浅主题和图表样式能力整理成更高效、更克制的工作台体验。优化重点不是继续增加装饰，而是减少操作阻力：让用户能按任务调整编辑与预览空间，在不遮暗预览的情况下实时修改样式，并在桌面和移动设备上快速操作画布。

目标用户仍是在浏览器中编辑一个包含多张 Mermaid 图表的文档，并反复执行“选择图表、修改源码、检查预览、调整样式、导出结果”的用户。

完成后的结果应满足：

- 桌面三栏可以按任务调整比例，图表列表可以折叠。
- 样式检查器在桌面不再使用模态遮罩，调整时预览保持可见和可操作。
- 预览提供缩放、适配、平移和全屏能力，但不改变图表内容或导出尺寸。
- 移动端减少顶部动作密度，把主面板切换放在稳定的底部操作区。
- 深浅主题遵循同一套克制视觉规则，图表继续是第一视觉焦点。

## 方案选择

讨论过三种方向：

1. **平衡型工作台**：保留多图表列表和双编辑模式，增加可调分栏、非模态样式检查器和画布工具。
2. **预览优先工作台**：默认隐藏列表和部分编辑区域，让画布占据绝大部分空间。
3. **渐进式精修**：保持现有结构，只压缩工具栏并补少量画布按钮。

采用第一种方案。它直接解决空间分配、样式对照和画布操作问题，同时保留 xmermaid-live 相比 mermaid.live 更重要的多图表工作流。预览优先方案会削弱多图表效率；渐进式精修无法解决固定三栏和模态抽屉带来的核心摩擦。

## 目标桌面界面

下图是目标结构，表达区域关系和动作层级；具体像素比例和占位文字不构成约束。

```text
┌ xmermaid live ─────────────── [主题] [样式] [分享] [导出] ┐
├────────────┬─┬────────────────────┬─┬────────────────────┤
│ 图表   [‹] │↔│ 完整文本 | 当前图表 │↔│ 预览  [-][适配][+][全屏] │
│            │ │                    │ │                    │
│ 图表 1     │ │ 源码编辑器          │ │ Mermaid SVG        │
│ 图表 2     │ │                    │ │                    │
│ 图表 3     │ │                    │ │                    │
├────────────┴─┴────────────────────┴─┴────────────────────┤
│ ● 已更新 / 无诊断                                      [展开] │
└─────────────────────────────────────────────────────────┘
```

稳定约束：

- 两个分隔条可调整列表、编辑器和预览的相对宽度。
- 编辑器和预览都有可用最小宽度，拖动不得把任一主任务区域压缩到不可操作。
- 图表列表可折叠；恢复后保留选择和滚动位置。
- 顶部工具栏只承载全局动作，画布操作留在预览标题区域。
- 底部状态栏默认单行，存在详细诊断时可以展开。

### 桌面样式检查器

打开样式后，预览区域内部形成画布与检查器的并列关系，不重新改变列表和编辑器宽度：

```text
目标状态：桌面样式检查器已打开

┌─ 预览画布 ─────────────────┬─ 图表样式 ───────────────┐
│                            │ 预设 / 颜色 / 几何 / 文字 │
│ SVG 保持可见、可缩放        │ 实时修改，不加全屏遮罩     │
└────────────────────────────┴───────────────────────────┘
```

检查器是非模态区域。用户可以在它打开时继续操作画布、编辑器和图表列表。画布处于“适配”模式时，检查器打开或关闭会根据新的可见区域重新计算适配比例；手动缩放模式不会被自动覆盖。

常用的主题、曲线、箭头和尺寸设置直接显示。颜色与字体等低频设置使用渐进披露，降低首次打开时的视觉密度。关闭检查器后预览恢复全部可用宽度，并把焦点返回样式入口。

## 目标移动界面

移动端和平板空间不足时保持单主面板，不强行恢复三栏。

```text
目标移动布局

┌ xmermaid live ───────────── [主题] [样式] [更多] ┐
│                                                 │
│ 当前主面板                                      │
│                                                 │
│ 编辑：源码占满可用高度                           │
│ 预览：画布 + 浮动缩放工具                        │
│ 图表：可滚动图表列表                             │
│                                                 │
├─────────────────────────────────────────────────┤
│   图表              编辑              预览       │
└────────────────────── 安全区 ────────────────────┘
```

移动端稳定约束：

- “图表 / 编辑 / 预览”位于底部标签栏，使用图标和短文字共同表达含义。
- 顶部只保留品牌、主题、样式和更多菜单；分享与导出进入更多菜单。
- 选择图表后自动进入编辑面板；返回列表时保留滚动位置。
- 预览面板提供缩小、适配、放大和全屏工具。
- 样式设置使用全高 sheet，顶部使用明确的标题与“完成”动作；关闭后返回原面板并恢复焦点。
- 诊断错误在相关标签显示非纯颜色状态，进入预览后可展开详细诊断。
- 底部标签栏、软键盘和安全区不得覆盖源码、画布或输入光标。

## 克制的视觉语言

“Apple 一样克制”在本项目中表示纪律化的信息层级，而不是复制 macOS 品牌或控件外观。

- 使用系统字体栈；等宽字体只用于品牌小标、源码、数值和诊断。
- 深色使用近黑与中性灰表面，浅色使用冷白与纯白表面。青绿色只表达主状态、选择和焦点；珊瑚与琥珀只表达错误和警告。
- 普通工具动作默认使用透明背景，悬停或激活时才出现浅表面。主题、曲线等模式继续使用分段控件。
- 熟悉的画布动作使用图标按钮，并提供 tooltip 和可访问名称；分享、导出等明确命令保留图标与文字。
- 使用低对比度 hairline 分隔区域，不把页面区域改成浮动卡片，也不嵌套卡片。
- 圆角保持在 6 至 8 像素。阴影只用于真正浮起的菜单，不用于固定面板。
- 预览点阵降低对比度，避免与图表节点和连线争夺注意力。
- 状态过渡采用约 160ms 的轻微淡入或位移；拖动、平移和缩放保持即时反馈，并尊重 `prefers-reduced-motion`。
- 深浅主题使用相同空间结构、控件尺寸和视觉重量。

## 交互与状态模型

```text
用户操作
   ├─ 拖动分栏 / 折叠列表 ──> WorkspaceLayoutPreferences
   ├─ 缩放 / 平移 / 适配 ───> CanvasViewport
   ├─ 打开样式检查器 ───────> InspectorState
   └─ 修改图表样式 ─────────> 现有 ThemePreferences
                                      │
                                      ▼
                               PreviewRuntime
```

### 布局偏好

分栏宽度和列表折叠状态保存在独立、版本化的本地布局偏好中。它不与图表主题偏好混用，也不进入分享链接。偏好缺失、版本不匹配、数值越界或存储不可用时恢复默认比例。

分隔条支持指针拖动和键盘调整。双击分隔条恢复默认比例。拖动只更新 CSS 布局并通过 `requestAnimationFrame` 合并视觉更新，不触发 xmermaid 或 WASM 重新渲染。

### 画布视口

画布缩放范围为 25% 至 400%，支持按钮、`Ctrl/Cmd + 滚轮` 和触控板。放大后可通过拖动或触控板平移。查看状态只改变画布呈现，不修改 SVG、主题或导出尺寸。

“适配”根据当前可见画布区域计算比例。窗口、分栏或样式检查器尺寸变化时，只有处于适配模式的画布自动重算；手动缩放和平移保持用户选择。

切换到一张尚未查看的图表时默认适配。返回当前会话中已经查看过的图表时恢复该图表的视口。视口状态不跨刷新持久化，也不进入分享链接。

全屏优先使用浏览器 Fullscreen API。浏览器不支持、用户拒绝或调用失败时，回退为应用内最大化预览。退出后恢复原分栏、检查器和焦点状态。

## 状态反馈与失败处理

- 状态栏区分“已更新”“正在渲染”“预览过期”和“存在诊断”，不把布局拖动误报为重新渲染。
- 图表渲染失败继续保留最后成功 SVG，并禁用与当前源码或主题不匹配的导出。
- 无效布局偏好静默恢复默认值；本地存储读写失败不阻塞编辑、预览或导出。
- `ResizeObserver` 不可用时，在窗口和明确布局动作后执行适配计算。
- Fullscreen API 失败时使用应用内最大化，并在状态区域提供简短反馈。
- 非模态检查器和桌面分栏保持正常 Tab 顺序；移动 sheet 使用模态焦点约束，关闭后恢复到入口。

## 实现责任边界

本轮只修改 xmermaid-live，不改变 xmermaid 的布局、渲染、主题或导出合同。

新增两个无 DOM 依赖的状态模块：

- `layout-preferences` 负责分栏、折叠、约束、版本化序列化和回退。
- `canvas-viewport` 负责缩放、适配、平移、每图会话状态和坐标计算。

应用入口继续负责 DOM 事件、焦点、面板编排和把状态结果映射到界面。图标使用仓库内最小 SVG 图标集合，统一尺寸、线宽、tooltip 和可访问名称；不新增前端框架、图标包或通用状态管理层。

## 质量目标

### 交互能力：易操作与包容性

用户可以通过键盘、鼠标和触控完成分栏调整、列表折叠、画布查看、样式修改和主面板切换。移动触控目标不小于 44 像素；焦点、选中和诊断状态不只依赖颜色。证据为 DOM 语义测试、键盘路径、触控尺寸检查和真实浏览器操作。

### 性能效率：时间特性与资源利用

分栏拖动和画布平移不触发 WASM 渲染；连续指针更新通过动画帧合并。证据为渲染器调用计数测试、浏览器事件检查和交互期间控制台观测。

### 可靠性：容错与可恢复性

布局偏好无效、存储异常、Fullscreen API 失败或 `ResizeObserver` 缺失时，用户仍可继续编辑、预览和导出，并能回到可用默认布局。证据为异常路径单测和浏览器回退测试。

### 可维护性：模块化与可测试性

布局偏好和视口数学可以在无 DOM 环境中独立测试；应用层只消费明确的状态结果。证据为纯函数单测、类型检查和代码评审。

## 验证设计

### 自动化验证

- 单测覆盖缩放上下限、适配计算、平移约束、每图会话视口、布局偏好迁移和异常回退。
- 应用 DOM 测试覆盖非模态检查器、焦点返回、分隔条键盘操作、列表折叠、状态栏和全屏回退。
- Playwright 覆盖桌面拖动与刷新恢复、画布缩放和平移、样式实时对照、移动底部导航和样式 sheet。
- 测试证明布局拖动和画布平移不会增加 PreviewRuntime 渲染请求。
- TypeScript、Vitest、生产构建、Playwright 和 `git diff --check` 全部通过。

### 视觉与响应式验证

在以下视口检查文字、控件、工具条、面板和安全区无重叠或裁切：

- 1440 x 900 桌面。
- 1024 x 768 平板或紧凑桌面。
- 390 x 844 常见移动设备。
- 320 x 568 最小支持移动视口。

重新生成深色桌面、浅色桌面和深色移动端截图。检查图表仍是第一视觉焦点、样式检查器打开时预览可见、顶部与底部工具不争夺内容空间，并确认主要路径没有控制台错误。

## 本轮边界

本轮不包含语法高亮、行号、撤销历史、图表搜索或新的 xmermaid 渲染能力。这些能力会改变编辑器或渲染器责任，适合作为后续独立议题。

现有主题持久化、分享编码、多图表选择、SVG/PNG 导出、诊断语义和箭头几何必须保持兼容。

## 完成条件

- 桌面用户可以调整三栏、折叠列表，并在非模态检查器中对照预览修改样式。
- 画布缩放、适配、平移和全屏不改变 SVG 内容或导出结果。
- 移动端顶部动作更紧凑，底部主导航和样式 sheet 在最小支持视口内完整可用。
- 深浅主题符合确认的克制视觉语言，主要状态清楚且不过度使用强调色、边框或阴影。
- 所有选中质量目标都有对应自动化或浏览器证据，现有编辑、预览、分享、导出和诊断路径不回归。
