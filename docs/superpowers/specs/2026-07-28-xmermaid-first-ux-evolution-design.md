# xmermaid-first 工作台与渲染演进设计

状态：已通过对话确认，待书面规格复核  
日期：2026-07-28

## 决策

xmermaid-live 是 xmermaid 的日常使用工作台，也是发现、验证并推动 xmermaid 演进的主场。所有预览都必须由 xmermaid 渲染；不接入 Mermaid 官方渲染器或任何兼容渲染器作为回退，以免能力缺口被掩盖而无法形成正向反馈。

“支持更多 Mermaid 图表”因此不是在应用层换引擎，而是让 xmermaid 的解析、布局和 SVG 渲染能力逐步覆盖更多图表族。应用必须准确呈现当前支持状态，保留用户源码，并把每一次缺口转化为可复现的 xmermaid 输入、诊断与回归样例。

本规格替代此前“混合渲染器”方向；已确认的深浅主题、三栏工作台、画布导航、浏览器缓存和箭头几何原则继续有效。

## 真问题与目标

用户需要一个可每天使用的图表编辑器，而不是展示 xmermaid 能力的样例页。它既要有简洁、克制、有质感的 UI/UX，也要在真实文档中暴露渲染问题并让问题可定位、可修复、可验证。

完成后的产品应当：

- 默认提供深色优先、同等完成度的浅色主题；预览始终是页面视觉重心。
- 让每一个 Mermaid fenced block 留在图表列表中，明确其图表类型、xmermaid 支持状态和诊断。
- 在 xmermaid 已支持的图表中提供可靠、能力匹配的样式与画布控制。
- 对未支持或部分支持的图表保留源码、展示精确恢复路径，并自动沉淀可复现样例。
- 把真实使用中发现的曲线、箭头、解析和布局缺陷，持续回流到 xmermaid 的测试与发布包。

## 目标工作台

```text
目标：桌面工作台

┌ xmermaid live · 文档状态 ───────── [主题] [样式] [分享] [导出] ┐
├─────────────────┬──────────────────────────┬───────────────────┤
│ 图表             │ 源码 / 诊断              │ 预览              │
│ 支持状态、类型    │ 完整文档 / 当前图表       │ 画布、缩略图、视图 │
│ 收起后恢复轨      │ 可恢复错误信息             │ xmermaid 状态      │
├─────────────────┴──────────────────────────┴───────────────────┤
│ 已更新 / 渲染中 / 预览过期 / 诊断与恢复动作                      │
└────────────────────────────────────────────────────────────────┘
```

稳定关系：顶栏只放全局动作；预览内只保留一组视图控制，不重复全屏；收起图表列表后始终保留恢复轨；源码、诊断与相关图表在同一任务上下文中；预览、导出和状态均标明 xmermaid 版本与渲染状态。

移动端保留有文字的“图表 / 编辑 / 预览”底部导航。中屏把图表列表收进可恢复抽屉，不强行保留三栏。所有关键触控目标至少为 44px，画布操作始终有可见按钮和键盘替代方式。

## 信息与反馈模型

通用 fenced-block 扫描器先保存每个块的源码、位置和推断类型；随后由 xmermaid 能力目录为该块标记 `supported`、`partial` 或 `planned`。列表和预览绝不因为类型未知而变成“没有找到图表”。

```text
输入源码
  → fenced-block 扫描与类型识别
  → xmermaid 能力检查
  → 渲染 / 精确诊断
  → 使用样例与失败快照
  → xmermaid 修复、测试、打包
  → xmermaid-live 日常验证
```

- `supported`：正常渲染，并显示适用的样式控制。
- `partial`：保留可渲染内容，显示具体未覆盖的语法和“复制复现样例”动作。
- `planned`：显示该图表类型与首个不支持结构，保留源码并提供复制样例与诊断；不伪造空预览。
- 渲染错误：保留最后一次成功 SVG，以状态条和源码附近的错误说明当前预览过期、原因与下一步。
- 诊断必须有文本和图标，不以颜色单独表达；错误区域使用 `aria-live`。

能力目录是应用和 xmermaid 之间的明确合同：它决定列表标签、样式检查器可见项、诊断文案和测试样例，不能由 UI 临时猜测。

## 图表能力演进

优先顺序以真实编辑器使用与 Mermaid 常见语法为准：

1. 补齐 Flowchart：分支、子图、方向、节点形状、曲线与箭头。
2. 在 xmermaid 内新增 Sequence、Class、State、ER。
3. 继续覆盖 Gantt、Pie、Mindmap；每个图表族先定义可接受子集、错误模型和扩展路径。

每一族都必须拥有 xmermaid 的解析样例、布局/渲染测试、SVG 快照或语义断言，以及 xmermaid-live 端到端验证。应用不因为某一族暂未完成而切换另一个渲染器。

## 箭头与连线契约

箭头几何属于 xmermaid 渲染责任，应用只消费打包产物并做浏览器验收。

- 折线最终可见段必须沿目标节点边界法线进入节点；marker 方向从该最终段导出。
- 贝塞尔 marker 方向使用裁剪后的三次曲线终点导数 `P3 - P2`，而不是旧的布局切线缓存。
- 直线、贝塞尔和折线的路径终点都按当前箭头形状、大小、边界间距与线宽计算；`edgeGap` 只表达节点与箭头的留白，不制造连线与箭头间的缝隙。
- 对所有已支持箭头类型和基本方向，最终可见路径切线与 marker 轴线的误差不超过 5°；连接处无可见间隙、无非预期穿入节点。

## 视觉与交互语言

视觉遵循“克制的精密工具”，而不是模仿 Apple 或使用装饰性科技感：

- 深色使用近黑石墨底、低发光层级和靛蓝焦点色；避开纯黑、大面积渐变、霓虹和无目的模糊。
- 浅色使用暖白、石墨文字和同一语义强调色；深浅主题保持结构、密度与交互重量一致。
- 使用 8px 间距节奏、14px 可交互容器圆角、细半透明边界；阴影只用于菜单和临时悬浮层。
- 使用系统无衬线字体；源码、数值和诊断采用等宽字体。正常文字与背景对比度至少达到 WCAG AA。
- 动效只表达状态变化：150–200ms 的透明度或位移，拖动和缩放即时响应，并遵从 `prefers-reduced-motion`。

画布支持滚轮缩放、拖拽平移、适配、100% 重置、单一全屏入口和缩略图。视图状态以指针为锚点缩放，切换图表后保留该图表的会话视图。画布动作不改 SVG 内容或导出尺寸。

样式检查器由能力目录驱动：Flowchart 显示曲线、箭头、节点形状等 xmermaid 已支持的选项；其他图表族只显示当前真实有效的选项，绝不保留无效控件。

## 本地数据与恢复

浏览器本地缓存版本化保存文档、当前图表、主题、样式、面板与视图偏好；页面明确说明数据只保存在本机，并提供清除入口。无效缓存、版本不匹配或存储不可用时，回退到可编辑的默认文档而不阻塞编辑器。

用户的源码不得因渲染失败、未知类型或缓存恢复失败而丢失。分享与导出只使用当前确定的 xmermaid 成功预览；预览过期时明确标记并禁用不匹配的导出。

## 质量目标与证据

### 功能适宜性与兼容性

每个识别出的 Mermaid 代码块都在列表中可见，并拥有准确的 xmermaid 能力状态。新增图表族在 xmermaid 内实现、打包并由 xmermaid-live 消费。证据：扫描器单测、能力目录测试、xmermaid 消费包 smoke 和多图表 E2E。

### 交互能力与可靠性

用户在错误、部分支持、收起列表、缩放平移和缓存恢复状态下，仍可定位源码、恢复预览或复制复现信息。证据：DOM 语义和焦点测试、真实浏览器失败路径、键盘/移动设备 E2E 与本地缓存恢复测试。

### 可维护性与可测试性

图表扫描、能力判断、视图状态、渲染状态和 SVG 几何分别保持无 DOM 或可独立验证的边界。每个 xmermaid 修复必须附带最小复现样例和回归测试；应用层不修补 SVG 几何。证据：xmermaid 单测、SVG 语义/角度检查、CDP 真实渲染检查、TypeScript 与 Playwright 全量验证。

### 性能效率

编辑、缩放和平移不会引入不必要的重复渲染；连续视图事件按动画帧合并。证据：渲染调用计数测试和浏览器交互检查。

## 实施批次

1. 建立支持状态、通用块扫描和诊断恢复界面，先消除“图表消失”。
2. 在 xmermaid 修复 Step / Bézier 箭头末端几何，并用路径切线角度、连接距离的单测与 CDP 验收锁定行为。
3. 以 xmermaid 为唯一渲染引擎，按优先级增加图表族与能力目录；每一族在打包产物和 live 工作台中验收。
4. 将样式检查器、移动布局和可访问性绑定到能力目录，保持深浅主题的视觉统一。
5. 完成缓存、样例复制、截图基线和跨浏览器回归，形成日常使用的反馈闭环。

## 完成与循环条件

本轮的终点不是“用另一个引擎显示所有图”，而是完成第一批 xmermaid-first 工作台基础：所有图表块可见且有准确状态；受支持 Flowchart 的箭头几何已通过严格回归；xmermaid 具有扩展新图表族所需的样例、能力目录和打包验收链路。

之后每个真实使用中发现的问题都以“最小输入 → xmermaid 回归测试 → 渲染修复 → 打包 → xmermaid-live E2E”闭环，持续提升 xmermaid 本身。
