# xmermaid-first 工作台与渲染演进设计

状态：已通过对话确认，待书面规格复核  
日期：2026-07-28

## 决策

xmermaid-live 是 xmermaid 的日常使用工作台，也是发现、验证并推动 xmermaid 演进的主场。所有预览都必须由 xmermaid 渲染；不接入 Mermaid 官方渲染器或任何兼容渲染器作为回退，以免能力缺口被掩盖而无法形成正向反馈。

“支持更多 Mermaid 图表”因此不是在应用层换引擎，而是让 xmermaid 的解析、布局和 SVG 渲染能力逐步覆盖 Mermaid 官方语法目录中的全部常见图表族。应用必须准确呈现当前支持状态，保留用户源码，并把每一次缺口转化为可复现的 xmermaid 输入、诊断与回归样例。

本规格替代此前“混合渲染器”方向；已确认的深浅主题、三栏工作台、画布导航、浏览器缓存和箭头几何原则继续有效。

## 真问题与目标

用户需要一个可每天使用的图表编辑器，而不是展示 xmermaid 能力的样例页。它既要有简洁、克制、有质感的 UI/UX，也要在真实文档中暴露渲染问题并让问题可定位、可修复、可验证。

完成后的产品应当：

- 默认提供深色优先、同等完成度的浅色主题；紫蓝冷光的品牌张力取代当前青绿色工业感，预览始终是页面视觉重心。
- 让每一个 Mermaid fenced block 留在图表列表中，明确其图表类型、xmermaid 支持状态和诊断。
- 在 xmermaid 已支持的图表中提供可靠、能力匹配的样式与画布控制。
- 对未支持或部分支持的图表保留源码、展示精确恢复路径，并自动沉淀可复现样例。
- 把真实使用中发现的曲线、箭头、解析和布局缺陷，持续回流到 xmermaid 的测试与发布包。

## 目标工作台

```text
目标：桌面工作台

┌ xmermaid live · 文档状态 ───────── [主题] [样式] [分享] [导出] ┐
├─────────────────┬──────────────────────────┬───────────────────┤
│ 图表             │ 源码 / 诊断              │ 预览              │
│ 支持状态、类型    │ 完整文档 / 当前图表       │ 画布、缩略图、视图 │
│ 收起后恢复轨      │ 可恢复错误信息             │ xmermaid 状态      │
├─────────────────┴──────────────────────────┴───────────────────┤
│ 已更新 / 渲染中 / 预览过期 / 诊断与恢复动作                      │
└────────────────────────────────────────────────────────────────┘
```

稳定关系：顶栏只放全局动作；预览内只保留一组视图控制，不重复全屏；收起图表列表后始终保留恢复轨；源码、诊断与相关图表在同一任务上下文中；预览、导出和状态均标明 xmermaid 版本与渲染状态。

移动端保留有文字的“图表 / 编辑 / 预览”底部导航。中屏把图表列表收进可恢复抽屉，不强行保留三栏。所有关键触控目标至少为 44px，画布操作始终有可见按钮和键盘替代方式。

## 信息与反馈模型

输入扫描器保存每个图表的源码、位置、输入形态和推断类型；随后由 xmermaid 能力目录为该块标记 `supported`、`partial` 或 `planned`。它必须识别三种既有输入，而不是只识别 fenced block：带 `mermaid` 标记的 fenced block、完整输入为单张裸 Mermaid 图表、以及含多张 fenced Mermaid 图表的 Markdown 文档。非 Mermaid fenced code、普通 Markdown 与空文档不产生伪图表。列表和预览绝不因为类型未知而变成“没有找到图表”。

```text
输入源码
  → fenced-block 扫描与类型识别
  → xmermaid 能力检查
  → 渲染 / 精确诊断
  → 使用样例与失败快照
  → xmermaid 修复、测试、打包
  → xmermaid-live 日常验证
```

- `supported`：正常渲染，并显示适用的样式控制。
- `partial`：保留可渲染内容，显示具体未覆盖的语法和“复制复现样例”动作。
- `planned`：显示该图表类型与首个不支持结构，保留源码并提供复制样例与诊断；不伪造空预览。
- 渲染错误：保留最后一次成功 SVG，以状态条和源码附近的错误说明当前预览过期、原因与下一步。
- 诊断必须有文本和图标，不以颜色单独表达；错误区域使用 `aria-live`。

能力目录是应用和 xmermaid 之间的明确合同：它决定列表标签、样式检查器可见项、诊断文案和测试样例，不能由 UI 临时猜测。

未支持状态不是空白失败，而是日常反馈入口：显示首个不支持的语法位置、稳定的能力缺口 ID、运行中的 xmermaid 版本、复制最小复现和导出源码动作。它不显示伪预览，也不要求用户改写为 Flowchart；恢复路径是把真实输入送回 xmermaid 的兼容性语料。

## 图表能力演进

兼容性基线跟随 Mermaid 官方 11.16.0 的图表语法目录，xmermaid 必须支持下列 30 个图表族，不以“仅 Flowchart”或应用层回退交付：

| 批次 | 图表族 |
| --- | --- |
| 关系与流程 | Flowchart、Swimlanes、Sequence、Class、State、Entity Relationship、User Journey、Requirement、GitGraph、C4、Mindmap、Timeline、ZenUML、Event Modeling、TreeView |
| 计划与数据 | Gantt、Pie、Quadrant、Sankey、XY Chart、Radar、Treemap、Venn、Ishikawa、Wardley、Cynefin |
| 工作与空间 | Block、Packet、Kanban、Architecture |

目录来源：[Mermaid Syntax Reference](https://mermaid.js.org/intro/syntax-reference.html)。

实现按真实使用率和共享布局原语推进，而不是按“容易画”挑选：先补齐 Flowchart，再完成 Sequence / Class / State / ER / Gantt / Pie / Mindmap 等日常核心族；随后完成其余官方目录类型。C4 与 Mermaid 标记为新能力的图表同样纳入覆盖，但它们的语法版本和兼容策略要在 xmermaid 的公共支持矩阵中可追踪。

每一族都必须拥有 xmermaid 的语法样例、解析测试、布局/渲染测试、SVG 快照或语义断言，以及 xmermaid-live 端到端验证。应用不因为某一族暂未完成而切换另一个渲染器；在正式支持前只显示准确状态和可复制的最小复现。

兼容性发布的完成条件是这 30 类全部进入 `supported`：官方有效示例可以解析、稳定渲染为 SVG、随深浅主题导出，并通过 xmermaid-live 的真实浏览器路径。`partial` 和 `planned` 只允许作为开发过程的透明状态，不能成为最终兼容性基线的替代品。

### 兼容性语料合同

兼容性目标固定为 Mermaid **11.16.0**。xmermaid 仓库保存版本化的 `fixtures/mermaid-11.16/`：每个图表族至少有一个最小有效样例、一个真实常用样例和一个预期诊断样例；样例记录官方来源 URL 与预期能力状态。升级 Mermaid 版本必须先单独更新语料和支持矩阵，再改变渲染行为，不能让远端文档的变动静默扩大本轮承诺。

一张图表只有同时满足以下条件才可以标为 `supported`：解析得到该图表族的类型化 AST；完成语义校验和布局；输出稳定 SVG；在深浅主题下可导出；在 xmermaid-live 的 Chromium、Firefox、WebKit 路径中可选择、缩放、复制和导出。`partial` 必须列出已支持子语法和首个缺口；`planned` 必须绑定到稳定的图表族 ID。

### xmermaid 架构边界

不要为 30 个图表强造一个巨大 Graph AST。xmermaid 采用“共享管线、族内模型”的边界：

```text
源文本 → 图表类型分派 → 族内 AST → 语义模型 → 族内布局 → 通用 Scene → SVG
                                  │                         │
                         Support manifest            DiagramTheme + 导出
```

- 类型分派、诊断、能力目录、Scene/SVG 基元、主题、导出和 WASM 边界是共享能力。
- 每个图表族拥有自己的 AST、语义校验、布局和样式能力；关系图可以复用节点/边/箭头原语，时间轴、统计图与空间图不被强迫伪装成关系图。
- `DiagramCapabilities` 由 xmermaid 导出，包含可用的样式组、交互限制和语法版本；live 只消费它，不手工维护第二套类型表。
- 每个新增族先在 `/Volumes/Data/Code/xmermaid` 通过 fixture、Rust/TypeScript 测试和 `npm pack` 消费 smoke，再更新 xmermaid-live 的 tarball 与浏览器 E2E。应用层不得修补 SVG 几何或把类型分派藏进 UI 条件分支。

日常循环使用可追溯本地预发布包：用户输入产生 fixture 或缺口 ID → xmermaid 修复与打包 → live 切换该 tarball → 三浏览器 E2E → 通过后成为下一稳定包。这样保持 xmermaid 为唯一渲染核心，同时让日常使用不是等待未来大版本的黑箱。

## 箭头与连线契约

箭头几何属于 xmermaid 渲染责任，应用只消费打包产物并做浏览器验收。

- 折线最终可见段必须沿目标节点边界法线进入节点；marker 方向从该最终段导出。
- 贝塞尔 marker 方向使用裁剪后的三次曲线终点导数 `P3 - P2`，而不是旧的布局切线缓存。
- 直线、贝塞尔和折线的路径终点都按当前箭头形状、大小、边界间距与线宽计算；`edgeGap` 只表达节点与箭头的留白，不制造连线与箭头间的缝隙。
- 对所有已支持箭头类型和基本方向，最终可见路径切线与 marker 轴线的误差不超过 5°；路径终点到 marker 连接基准的轴向误差在 -0.5 至 +1 CSS 像素内，marker 不得穿入节点轮廓超过 0.5 CSS 像素。
- 回归矩阵覆盖四个正交方向、斜向边、矩形/圆形/菱形/体育场节点、filled/triangle/open/circle/cross 箭头、straight/step/bezier 曲线，以及分支汇合的 TD 与 LR 图。几何单测从最终 SVG path 与 marker transform 计算，CDP 截图只作为第二层视觉证据。

## 视觉与交互语言

视觉目标是“创作型图表工具的精致张力”：参考 mermaid.live 的明快品牌感、清晰画布与轻盈层级，但保留 xmermaid-live 的多图表工作流，不复制其页面或控件。

| 语义 | 深色 | 浅色 |
| --- | --- | --- |
| 画布 | `#0D0B1A` | `#F8F7FF` |
| 主面板 | `#15112A` | `#FFFFFF` |
| 编辑器 / 内凹表面 | `#100D22` | `#FCFBFF` |
| 悬停表面 | `#211B3D` | `#F0EDFF` |
| 主要文字 | `#F4F1FF` | `#211A36` |
| 次级文字 | `#B9B1D4` | `#665E7D` |
| 品牌紫 | `#A78BFA` | `#6D28D9` |
| 冷蓝焦点 | `#67E8F9` | `#0891B2` |
| 强调渐变 | `#A78BFA → #6366F1 → #22D3EE` | `#7C3AED → #4F46E5 → #0891B2` |

- 渐变只用于品牌标识、选中态的细边、焦点环和一个明确的主命令；不用在页面背景、卡片、画布或装饰光球中铺满。这样保留“酷”的辨识度而不牺牲编辑内容的可读性。
- 深浅主题保持相同结构、密度与交互重量；深色不用青绿色工业 token，浅色也不退化成普通灰白后台。
- 使用 8px 间距节奏、8px 面板圆角、14px 可交互容器圆角、低对比度半透明边界；阴影只用于菜单和临时悬浮层。
- 使用系统无衬线字体；源码、数值和诊断采用等宽字体。正常文字与背景对比度至少达到 WCAG AA。
- 动效只表达状态变化：150–200ms 的透明度或位移，拖动和缩放即时响应，并遵从 `prefers-reduced-motion`。

工作台与图表不能只共享“颜色感觉”。xmermaid 必须导出配套 `DarkDiagramTheme` 与 `LightDiagramTheme`，至少覆盖节点填充/描边/文字、边、箭头、分组、数据系列、状态和诊断色；工作台 CSS token 与图表主题从同一语义名映射。每个主题以桌面深色、桌面浅色、移动深色和移动浅色截图作基线，评审检查图表是否仍是最高视觉优先级，而不是像素复制 mermaid.live。

画布支持滚轮缩放、拖拽平移、适配、100% 重置、单一全屏入口和缩略图。鼠标或触控板滚轮在画布内以指针为锚点缩放；Space + 拖拽、中键拖拽和触摸单指拖拽平移；文本编辑器和原生页面滚动不劫持这些事件。`+`、`-`、`0`、`F` 分别提供缩放、重置和适配的键盘等价操作。视图状态以指针为锚点缩放，切换图表后保留该图表的会话视图。画布动作不改 SVG 内容或导出尺寸。

样式检查器由能力目录驱动：Flowchart 显示曲线、箭头、节点形状等 xmermaid 已支持的选项；其他图表族只显示当前真实有效的选项，绝不保留无效控件。

## 本地数据与恢复

浏览器本地缓存使用 `WorkspaceCacheV2`，版本化保存文档、当前图表、主题、样式、面板与视图偏好；页面明确说明数据只保存在本机，并提供清除入口。写入按输入停止 250ms 后合并，单个缓存记录上限为 2 MiB；超限、QuotaExceeded、私密模式不可写或 JSON 校验失败时保留内存文档和上一次有效缓存，显示不打断编辑的恢复提示，绝不为腾空间自动删除用户文档。版本迁移必须是纯函数，未知未来版本只读失败并回退到默认示例，不覆盖原始存储键。

用户的源码不得因渲染失败、未知类型或缓存恢复失败而丢失。分享与导出只使用当前确定的 xmermaid 成功预览；预览过期时明确标记并禁用不匹配的导出。

## 质量目标与证据

### 功能适宜性与兼容性

每个识别出的 Mermaid 代码块都在列表中可见，并拥有准确的 xmermaid 能力状态；裸图表、混合 Markdown 和多图文档保持兼容。兼容性发布时 30 个图表族均在 xmermaid 内实现、打包并由 xmermaid-live 消费。证据：版本化 fixture 契约、扫描器单测、能力目录测试、xmermaid 消费包 smoke 和每类图表的多浏览器 E2E。

### 交互能力与可靠性

用户在错误、部分支持、收起列表、缩放平移和缓存恢复状态下，仍可定位源码、恢复预览或复制复现信息。所有主路径具有可见焦点、键盘等价操作和至少 44px 触控目标；正文文字对比度不低于 4.5:1，焦点和非文字控件不低于 3:1。证据：DOM 语义和焦点测试、真实浏览器失败路径、键盘/移动设备 E2E、对比度检查与本地缓存恢复测试。

### 可维护性与可测试性

图表扫描、能力判断、视图状态、渲染状态和 SVG 几何分别保持无 DOM 或可独立验证的边界。每个 xmermaid 修复必须附带最小复现样例和回归测试；应用层不修补 SVG 几何。证据：xmermaid 单测、SVG 语义/角度检查、CDP 真实渲染检查、TypeScript 与 Playwright 全量验证。

### 性能效率

编辑、缩放和平移不会引入不必要的重复渲染；连续视图事件按动画帧合并。缩放/平移的 50 个连续输入不得调用 xmermaid 渲染器，源码更新在 250ms 防抖窗口内至多发起一次最新渲染请求；渲染进行时维持上一次有效 SVG。证据：渲染调用计数测试、浏览器交互检查与过期请求回归测试。

## 实施批次

1. **兼容性地基**：固定 11.16.0 fixture 语料、类型注册、Support manifest、共享 Scene/SVG 原语与打包消费合同；同时修复扫描器，保持裸图表与 Markdown 兼容。
2. **正确性地基**：在 xmermaid 修复 Step / Bézier 箭头末端几何，用量化 SVG 几何与 CDP 验收锁定行为；完成缓存 V2、过期渲染和错误恢复。
3. **视觉地基**：交付紫蓝冷光的工作台与 `DarkDiagramTheme` / `LightDiagramTheme`，以截图、对比度和移动/键盘路径验收，不先改 UI 而让图表主题滞后。
4. **关系与流程图 epic**：Flowchart 完整化，再交付 Sequence、Class、State、ER、User Journey、Requirement、GitGraph、C4、Mindmap、Timeline、ZenUML、Event Modeling、TreeView 与 Swimlanes。
5. **计划与数据图 epic**：交付 Gantt、Pie、Quadrant、Sankey、XY Chart、Radar、Treemap、Venn、Ishikawa、Wardley、Cynefin。
6. **工作与空间图 epic**：交付 Block、Packet、Kanban、Architecture；随后运行完整 30 类兼容性发布矩阵。

## 完成与循环条件

“工作台基础完成”与“全图表兼容性发布”是两个不同门槛，不能混用。前者要求输入不消失、语料/能力目录/主题/缓存/箭头合同可运行；后者要求官方 11.16.0 的 30 类全部 `supported` 并通过固定 fixture、打包 smoke 与三浏览器 E2E。只有后者完成，才能声明 xmermaid 已完成这份官方图表兼容性基线。

之后每个真实使用中发现的问题都以“最小输入 → xmermaid 回归测试 → 渲染修复 → 打包 → xmermaid-live E2E”闭环，持续提升 xmermaid 本身。
